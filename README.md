# TruthTrace
上传聊天记录、截图和文件，AI 识别人物、还原事件、追踪承诺，并标出证据之间值得核查的差异，且每一条结论都可点回原始证据。
## 本机运行与模型连接

需要 Node.js 22.13+（推荐 24）和 Python 3。首次运行：

```bash
npm install
npm run build
npm run start:local
```

打开 `http://127.0.0.1:3000`。开发可用 `npm run dev:local`；只启动 `npm run dev` 时，钉钉连接按钮也会自动准备本机解析服务。缺失 Python 时页面会说明原因，安装 Python 后重试。启动不会先阻塞安装微信等无关渠道；完整依赖安装可单独运行 `npm run setup`。

助手 → 设置 → 模型设置 → 填写模型连接，选择 DeepSeek 时会预填官方地址与 `deepseek-flash`，填入自己的密钥后点击「连接并保存模型」。保存会验证文本与工具调用；Windows 下密钥经 DPAPI 保护后加密存于本机 `.truthtrace`。临时连接测试不等于保存，不能用于后台材料分析。其他系统使用 `AGENT_*` 环境变量配置。

共享连接用于对话、材料分析与调查；没有模型时仅做明确标注的规则统计，不能当作语义分析。模型失败时导入流程保留材料并显示原因。已有案件点击「用模型分析已有材料」即可重新生成关系与时间线，不必重新导入，旧分析保存在本机历史表。

钉钉：选择渠道 → 连接钉钉。系统自动准备读取服务和 CLI，已有有效授权会直接继续；未授权则显示官方设备授权二维码和链接，用户用钉钉扫码确认。之后按联系人/群名选择会话。微信使用不同的本机接入机制，不能承诺仅扫码即可完成。

当前自动材料分析以文本为主；未参与分析的图片会明确标出。调查/对话的原图发送仍需用户勾选授权。模型通过原文编号引用，程序还原逐字引文并验证引用；语义判断仍需要结合上下文复核。

## GitHub Pages 与完整应用

完整应用依赖 Next.js API、SQLite、Python 解析服务和本机授权，不能用静态托管替代。`npm run build` 保留服务端 API。`node scripts/build-static.mjs` 只生成项目说明页，不移动源码、不删除 `.next`、不伪装在线 Agent。Pages 展示页不会接收密钥或聊天。部署完整服务需要可持续运行 Node/Python 的环境；访问本机钉钉仍需本机服务。

## 数据契约

`src/lib/contracts.ts` 定义 `Evidence`、`AnalysisResult`（人物、关系、事件、矛盾、承诺、补证建议），并以 Zod 校验。前端只消费经过校验的结构化结果，不理解 MCP 或模型提示词。

## 当前部署边界

当前升级候选面向本机单用户使用，所有服务绑定回环，敏感API需要本机会话或明确机器凭据；remote模式拒绝访问，尚不具备团队或公网发布资格。材料、证据版本、调查和会话均持久化到SQLite；PDF/图片处理取决于解析依赖及明确授权。模型、规则和演示模式分别标识，引用合法不等于事实真实。

## 接续验收（2026-11-01）

当前框架适合三人并行完成黑客松原型；尚不代表生产环境或真实模型效果已验证。

- A：保持 POST /parse 的 file 字段与 Evidence 契约；验收文本、截图 OCR、PDF、空文件和服务超时。每份证据使用唯一 ID；文本引文必须能在 content 中逐字定位。
- B：维护 API 和分析校验。输入错误返回 400，模型调用或输出失败返回 502；不向浏览器回传模型服务原始错误。真实模型文本引用须匹配原文，图像引用仍需人工核验。后续完成真实模型回归集、身份消歧与部署访问控制。
- C：保留 mock/model 标识、错误反馈和证据回溯；验收空态、上传失败、分析失败和移动端布局。消费现有 AnalysisResult，不自行改变 API 字段。

GitHub Actions 对推送和 PR 执行 lint、测试、生产构建及类型检查。当前已补本机访问控制、持久化、请求体积/频率边界；团队权限、恶意文件全路径隔离及独立安全评审仍未完成，不宜公开接收敏感材料。

## 对话 Agent

点击右下角「和咪探长聊聊」可直接对话或围绕当前案件追问。模型设置包含 18 家供应商预设及自定义接口，支持 Chat Completions、Anthropic Messages 和 Responses；无需密钥可体验明确标注的本地演示。使用与配置详见 [Agent 文档](docs/AGENT.md)。

浏览器回归：运行应用后执行 `npx playwright install chromium` 和 `npm run test:browser`。

## 按目标调查（2026-11-03）

首页直接输入问题，或打开「和咪探长聊聊」。普通提问留在对话；调查与补充材料共用一个助手入口。已配置支持工具调用的模型时使用模型判断意图，配置缺失或分类失败时回退到规则。调查方式自动安排，可在「调整调查范围」里选择单点核查、时间线或完整调查。

选择钉钉时，授权完成后自动列出最近一周会话，支持按联系人或群名搜索，默认不勾选。只有选定内容会导入案件；扫描清单可能涉及渠道读取，覆盖范围以页面提示为准。也可以上传文件或截图。目标会随案件保存，切换模型设置时保留草稿。

开始核查前检查模型和后台服务；服务未运行时自动启动，也可点击重试。完成后优先显示针对目标的回答、未解决的问题和原文依据，技术过程折叠展示。补充材料会保存到同一案件，并将已有调查排队重新核查；旧执行结果不能覆盖新的修订。需要用户补充信息时显示具体问题，支持自由回答或暂时无法确认。

三种方式均保留证据读取、主张提取、独立核查和报告。调查方式随任务持久保存，旧任务继续使用八阶段；修订目标沿用原方式，更换方式需在原任务结束后新建调查。回答引用必须来自已独立核查的主张；这不等于自动保证事实正确，仍须结合支持状态、原文和缺口判断。

当前案件与调查任务已支持本地 SQLite 持久化。上文早期内存态及未接入能力描述为历史验收记录，以当前实现为准。

验证：`npm test`；构建后执行 `npm run test:investigator` 和 `npm run test:journey`。前者覆盖统一入口、引用回答、补充材料自动续查、刷新与移动端；后者覆盖目标草稿、钉钉授权衔接、按群名选择、限定导入和设置返回。两者均使用隔离目录及模拟数据，不读取真实聊天。普通对话与三种模型协议使用 `npm run test:browser` 回归。
