# R3 / R8 security repair

R3: Python channel-model HTTP now resolves once, rejects non-global addresses unless the exact origin is explicitly configured in TRUTHTRACE_MODEL_PRIVATE_ORIGINS, connects directly to the validated sockaddr and retains hostname TLS verification. HTTP requires explicit origin permission. Redirect statuses are rejected without contacting the new destination. Environment proxy settings cannot override the pinned connection. Upstream bodies/keys/URLs are never included in public errors. Response limit is 8 MiB. A wall-clock deadline capped at 60 seconds bounds caller DNS waits and interrupts the active socket during connect, TLS handshake and response reads. TLS socket ownership is transferred under the same lock used by expiry before explicit handshake. At most eight OS DNS resolver threads run concurrently; timed-out DNS cannot be cancelled and occupies its slot until the OS returns. Synchronous JSON encoding/decoding cannot be preempted; an elapsed deadline rejects the result after decoding, so this is not a hard CPU deadline.

R8: uploaded channel copies live under TRUTHTRACE_HANDLE_DIR (default temporary truthtrace-upload-handles), distinct from registered channel originals. Defaults: TRUTHTRACE_HANDLE_MAX_BYTES=26214400, TRUTHTRACE_HANDLE_TOTAL_BYTES=262144000, TRUTHTRACE_HANDLE_MAX_COUNT=256, TRUTHTRACE_HANDLE_TTL_SECONDS=86400. Overrides can lower limits only. Cleanup is lazy on upload, and only removes owned tt-UUID files. A cross-process OS lock serializes reservations, writes, expiry cleanup and active handle-consuming operations. Existing user-owned paths registered by channel adapters are never deleted. Failed uploaded conversations are removed; stale in-memory mappings are pruned on new upload. Locking may serialize long handle operations. Windows uses explicit nonblocking retries with a 60-second wait deadline instead of LK_LOCK's implicit approximately nine-second failure; callers receive safe service errors if that deadline expires. POSIX flock still waits for the lock without a deadline.

GET /health remains anonymous liveness; GET /health/auth requires the service Bearer token and returns only status/authenticated (no secret). Node must distinguish liveness from authenticated readiness to detect stale-token/old-service cases.

Validation: the original 7 isolated review tests passed (real HTTP redirect leak regression, explicit local-model success, unauthorized local destination rejection, quota/count/TTL, concurrent writers, active-reader exclusion, authenticated health and failed upload cleanup); existing 13 security tests passed; all 14 offline ingestion regression suites passed. Follow-up regressions cover slow-response and DNS total deadlines, Windows contention beyond ten seconds, and TLS ownership during handshake. Windows OS locking path executed. POSIX flock branch reviewed but not executed here. No real models, accounts, channel probes or private files were used.
