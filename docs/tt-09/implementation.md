# TT09 persistent case conversations

New conversations table uses the existing local SQLite database via an independent module, without changes to Store or Investigator runtime. Rows bind random conversation ID to case ID. Every read/edit/delete/append checks the case; API uses secureRoute. A case-delete trigger removes its conversations. Reply persistence uses an explicit allowlist; request connection, API key and provider transport bodies are not saved. User-authored message text itself is stored, so users should not paste secrets into chat.

Successful turns atomically append user and assistant messages with historical reference versions. Revision compare-and-swap rejects late model output after edit/delete or a competing request. Failed/cancelled questions stay in the UI draft, not partially committed as completed exchanges. Old nonpersistent sessions without conversationId still work. New saved-case sessions restore server history and ignore client-submitted previous turns; only the current user question is accepted. Unsaved/global sessions remain ephemeral.

UI supports restore, selecting prior conversations (latest 100), new conversation, edit, deleting a message and subsequent dependent answers, deleting a conversation, and clearing the cached context summary. Editing an assistant message converts it to user-authored text and removes its old citation badge. Edits invalidate dependent replies and summaries. Clearing summary clears the cached object; future long-history requests may derive a new excerpt from retained original turns.

Context preparation reserves the current question, keeps recent turns within 20,000 UTF-16 units, and adds at most 1,800 units of historical excerpts with turn indexes, source revision and reference versions. Summary is explicitly unverified historical data, added as user content, never system instructions. It is deterministic extraction, not a model factual summary. Every model call additionally checks a 48,000-character serialized text budget with a fixed image allowance; when exceeded it fails explicitly and keeps the saved conversation. UTF-8 byte token estimates and image allowances are approximations, not provider billing values. System policy remains separately constructed by runner; no history can supply system roles.

Limits: 300 turns and 1 MiB serialized conversation; users can start a new conversation. No real-model quality validation, task-link UI or cross-device sync. Archived references remain versions, not automatically current truth. Browser end-to-end refresh behavior should be validated by integration.

Validation: 153 unit tests passed, TypeScript and ESLint passed (existing channel-import image warning), webpack production build succeeded. Tests cover restart persistence, cross-case IDs, forged client history, revision conflicts, old reference versions, secret-field exclusion, deletion cascade and history budget/injection roles. Default Turbopack verification belongs to integration with physical node_modules, since this worktree uses a junction.

Rollback: revert TT09 application code; the additive table/trigger can remain for forward recovery. Back up the database before any manual table removal. Existing case/task data is not rewritten.
