## 2. 卡点：平台策略 21001（未解决）

建应用成功后，**任何** API 调用（含无权限要求的租户信息查询）都返回：

```json
{ "ok": false, "error": { "code": 21001,
  "message": "The requested scope is blocked by data security policy." } }
```

两条授权路线（应用身份 / 用户身份）在 token 签发阶段**同时被拦**。

**定性**：这是**平台策略层拒绝，不是代码问题**——与 App Secret、权限勾选、网络环境都无关。
常见两种成因：

1. 当前租户是**个人版**，不具备 OpenAPI 调用资质（开放平台要求企业/组织租户）。
2. 企业管理员在数据安全策略中**禁止了该应用的权限**。

**解除路径（按成功率排序）**：

| 方案 | 耗时 | 说明 |
| --- | --- | --- |
| 新建自有权租户（本人为组织负责人） | 约 10 分钟 | 最可行；高级权限可自助审批 |
| 企业管理员在后台放行该应用 | 视流程 | 需管理员配合 |
| 缩小授权范围重试 | — | 本例无权限接口也被拦，优先级最低 |

## 3. 演示怎么办

飞书端**暂不能演示真实取数**。建议：

- 用 `testdata/feishu_demo/` 的合成样例跑通「飞书 → 证据 → 分析」全链路，
  演示时**明确标注为合成数据**，不冒充真机。
- 把 21001 当作**对比素材**讲：微信端「本地库直读」不受企业策略约束，
  钉钉 / 飞书端受租户资质与管理员策略管辖——三端是**互补关系，不是替代关系**。
  这比"三端全绿"更能说明真实工程约束。

## 4. 若要真正打通，前置条件

按依赖顺序，缺一不可：

1. 一个**本人具有管理权限的飞书组织租户**（个人版不具备 OpenAPI 资质）。
2. 在该租户下创建自建应用，并开通 IM 消息相关权限。
3. 应用需**加入目标群**，且具备「获取群组中所有消息」敏感权限（读群历史的前提）。
4. 通过 `lark-cli` 完成一次成功的 token 签发（`auth status --verify` 确认）。
5. 用真实会话重跑适配器，补齐字段映射与边界情况（富文本、撤回、语音、群文件）。

> 完成第 4 步之前，不建议写实现设计——参数形态、返回字段、错误码都以真机为准，
> 提前写死容易在真机跑通后返工。
