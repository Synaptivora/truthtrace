# 批量导入与阅读呈现修复

问题：渠道范围内消息数不是HTTP请求大小。原上传/案件保存允许25 MiB，而`/api/analyze`误用普通控制请求2 MiB上限，3534条较长中文消息或携带图片时会在分析前被拒绝。

改动：仅把材料分析调整到已有25 MiB材料上限，其他JSON控制请求仍为2 MiB；认证、源校验、150 MiB并发预留、响应流生命周期和模型阅读预算保持原规则。客户端按UTF-8字节预检，超额提示缩小范围/减少图片附件。25 MiB不是条数保证，更不是模型已阅读所有材料；截断和未分析提示继续保留。原始材料不因模型预算而删除。

显示：增加单一CommonMark/GFM解析依赖marked（非新UI框架），统一对话、调查回答、工作台摘要、Markdown材料和HTML报告的标题、表格、嵌套列表、引用、代码呈现。HTML作为文本显示；不加载Markdown远程图片、不生成活动链接。来源字段和多行引文按字面转义，报告补齐段落边界和空章节说明；模型回答和摘要保留自身Markdown格式。Markdown材料可切换原始文本；精确引用仍使用原始字符范围高亮，不修改储存内容或位置。

排版：中文系统无衬线字体、默认16px阅读正文（较大18px）、更宽阅读窗口、更舒展的行距和控件。手机保持单列，表格/代码只在自身区域滚动。权限不在本次用户反馈范围内，未扩大材料访问范围。

验证：180项Vitest、lint无错误（既有img性能warning一项）、类型检查和生产构建。真实生产HTTP接收3534条合成聊天，UTF-8 JSON为2,451,613字节；浏览器验证Markdown表格/引用/代码、原文切换完全一致、16px字体、390px屏幕不横向溢出、报告预览和MD下载。既有搜索/历史定位/HTML及MD导出、对话持久化、调查员、渠道流程回归通过。搜索回归一次并行执行时浏览器意外关闭，单独重跑成功，未删除断言。

所有模型和材料验证使用隔离合成数据，未调用真实模型评估效果。截图由`scripts/reading-import-smoke.mjs`生成于`artifacts/reading`，不随仓库提交。运行：`npm test`、`npm run build`、`node scripts/reading-import-smoke.mjs`。
